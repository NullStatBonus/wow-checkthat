## Public API of CheckThat

What an addon that reports facts can rely on. It only grows: a released name, argument or line format does not change.

| Name | Contract | Since |
| --- | --- | --- |
| `CheckThat.API_VERSION` | Number, 4. Rises only when something is added. | 0.9.0 |
| `CheckThat.Entry(addon, name, fn)` | Returns true when it stores the entry, false otherwise. Never raises. An auto step with `call` runs it at step open, outside combat, and records `[addon] entry.<name>=<result>`. | 0.18.0 |
| `CheckThat.OnRun(addon, fn)` | Returns true when it stores `fn`, false otherwise. Never raises. One function per addon. Calls `fn("start" or "end", info)` in `pcall` for the open run of the current character when its plan names the addon. `info` is a new table: `plan`, `digest`, `runId`, and for `end` a `reason` of `ended`, `replaced` or `deleted`; that list is closed. `end` comes once per change of the open run. A reload or logout sends no `end`: the run stays open, and `start` comes again after the reload. `digest` is the plan's 32-bit Adler-32 checksum in hex; when two different plans stored on one machine share it, the later one gets `-2` (then `-3`), so the same plan can have another digest on another machine. | 1.0.0 |
| `CheckThat.ActiveRun(addon)` | The plan title of the current character's open run when its plan names the addon, else nil. Never raises. | 1.0.0 |
| `CheckThat.Commands(addon, list)` | Returns true when it stores the addon's slash command prefixes (1 to 8, each one word after a slash), false otherwise. Never raises. A later call replaces the list. A denied command (`/run`, `/script`, `/dump`, `/console`, the debug tools) or another known addon's command makes the whole call return false. A plan for the addon may then offer these commands without the in-game ownership check. | 1.0.0 |
| `CheckThat.Report(addon, key, value)` | Returns true when it records `[addon] key=value`, false otherwise. Never raises. Records only while a run is open. Limits: addon 32, key 48, string value 120 characters, 30 facts per addon per second, 300 lines kept. | 0.9.0 |
| `CheckThatDB.global.facts` | Array of the recorded lines, readable as a `strings` log. | 0.9.0 |
| `CheckThatDB.global.errors` | Array of Lua error lines recorded while a run is open, each `<time>.<counter> [<addon>] <message>` with the message cut to 200 characters, 100 kept, 30 a second. `<addon>` is read from `AddOns\<Name>\` in the message, else `?` (lines CheckThat adds itself say `CheckThat`). Readable as a quiet `strings` log. | 0.10.0, tag 0.12.0 |
| `CheckThatDB.global.blocked` | Array of up to 50 lines, each `<time>.<counter> [<addon>] <EVENT> <function>`, for `ADDON_ACTION_BLOCKED`, `ADDON_ACTION_FORBIDDEN`, `MACRO_ACTION_BLOCKED` and `MACRO_ACTION_FORBIDDEN` while a run is open (10 a second; `macro` for a macro event). Readable as a quiet `strings` log. BugGrabber's copies of these events are not in `global.errors`. | 1.0.0 |
| `CheckThatDB.global.errorStacks` | Array of up to 20 lines, each `<time>.<counter> <stack>` with the stack on one line, cut to 600 characters. The key matches the error line. The first error of a step only. No locals. | 0.12.0 |
| `CheckThatDB.global.runs[id].steps[sid].attempts[n].excerpt` | Table of source name to an array of at most 20 lines, each cut to 200 characters: the new lines of the log while a failed or unverified attempt was open. Added to the results string too. `ct` stays 1. | 0.13.0 |
| Fact values | A fact value reads as `true` or `false` (boolean), a number when the text is a plain decimal or exponent number, else text. `0x10`, `nan` and `inf` stay text. | 0.10.0 |
| `CheckThatDB.global.runs[id]` | Adds `categories` (list of id and title), `cat` (step id to category id) and `selected` (set of picked ids). A run without them reads as every section picked. Step verdict `deselected` is new. `ct` stays 1. | 0.10.0 |

Key bindings are part of the contract too (#252). The names stay, so a key a player bound keeps working:

| Name | Contract | Since |
| --- | --- | --- |
| `CHECKTHAT_PASS`, `CHECKTHAT_PARTIAL`, `CHECKTHAT_FAIL`, `CHECKTHAT_SKIP` | The binding names in `Bindings.xml`, under the header `CHECKTHAT` in Key Bindings, AddOns. | 0.16.0 |
| `CheckThat_Key(result)` | The global the bindings call with `"pass"`, `"partial"`, `"fail"` or `"skip"`. It records the result only while the card shows a step. | 0.16.0 |

Decisions, by part (the follow-up issues carry the build work):
- **Mocks offline: build.** Proven, no client needed. Next step is the plan format (mocks, entry calls, expectations) with schema, `Plan.lua`, `ct.py` and the format spec together.
- **Entry points and throws: built in 0.18.0 (#97).** Needed `CheckThat.Entry` in the public API (`API_VERSION` 2, a version bump) and an `auto` step that calls entries.
- **Fake events: build, offline only.** The real client cannot be made to fire arbitrary events.
- **Mocks in game: drop.** Local capture is not the blocker (0 captures), taint is. Measured on Era and Forever: a global that addon code replaces stays tainted after the original goes back, until `/reload`, and Blizzard money and vendor code reads those globals. Mocks stay offline.
- **Entry calls in game: allow with limits.** Registered entries only, outside combat, in `pcall`, with literal arguments. An entry must not call a protected function.
- **Setup and teardown: build with the plan format.** Mocks restore after the run today; per-step and per-category setup needs plan fields.
- **Login self-check: defer.** A separate, opt-in setting.

## Vendor, trainer and auction calls (source-reviewed 2026-11-26)

Read from Blizzard's UI source for each client with the wow-api source search. The generated API documentation lists the namespaced `C_` calls and, on Forever, a few legacy globals such as `GetMoney`; it does not show most of the globals below. The Forever source tree ships both the Vanilla and the Mainline interface files, and `Blizzard_UIPanels_Game.toc` loads the Vanilla files only for the vanilla game type, so a call that appears only in the Vanilla tree is not the one Forever uses. Which functions a client has comes from the census (`tools/clients/`). CTProbe's armed capture records what exists in game; this table says what to expect.

| Window | Era (1.15.9) | Forever (1.60.1) |
| --- | --- | --- |
| Vendor | `GetMerchantNumItems()`, `GetMerchantItemInfo(index)` returns name, texture, price, stackCount, numAvailable, isPurchasable, isUsable, extendedCost, currencyID, and `GetMerchantItemLink(index)`. | `GetMerchantNumItems` and `GetMerchantItemLink` exist. `GetMerchantItemInfo` appears only in the Vanilla tree, which Forever does not load, and is a nil global in game. Measured in game on 2026-11-26 with CTProbe v4 armed capture (Era 1.15.9.70576, Forever 1.60.1.71139):

- Era vendor: `GetMerchantItemInfo(index)` returns 9 values: name, texture, price in copper, stack count, number available (-1 is unlimited), isPurchasable, isUsable, extendedCost, and a nil currencyID. On the first visit to a vendor the name and `GetMerchantItemLink` were nil, because the items were not cached yet. A second visit returned both.
- Era trainer: `GetTrainerServiceInfo(index)` returns name, subText, type (`header`, `available` or `unavailable`) and a fourth value. `GetTrainerServiceCost` returns the cost in copper, and for a profession also `true`. `GetTrainerServiceSkillReq` returns the skill, the rank and whether the character has it. The first trainer event had no rows. The next update had them.
- Era auction: `GetNumAuctionItems("list")` returned 50 and 155 (this page, all pages). `GetAuctionItemInfo("list", index)` returned 18 values. The bidder and seller names were nil on list rows.
- Forever vendor: `GetMerchantNumItems()` and `GetMerchantItemLink(index)` work. `GetMerchantItemInfo` is a nil global. Use `C_MerchantFrame.GetItemInfo`, which returns a table (#234).
- Forever trainer: `GetTrainerServiceInfo(index)` returns name, type, texture, required level, subText (nil in the sample) and category, which is not Era's order. `GetNumTrainerServices()`, `GetTrainerServiceCost` and `GetTrainerServiceSkillReq` work.
- Forever item data: `GetItemInfo` is a nil global. `C_Item.GetItemInfo` works. Armor 12640 and weapon 12784 sell for 21894 and 73036 copper on both clients.

Item data: `C_Item.RequestLoadItemDataByID` exists on both clients. A recording keeps no table return, so the Forever auction calls and `C_MerchantFrame.GetItemInfo` are not recorded as they stand.

Added for CTProbe v5 to v7 (source-reviewed 2026-11-27, #240):

- `GetAuctionItemLink("list", index)` exists on Era only. `GetTrainerServiceLevelReq(index)` is in the Era source and not in the Forever source, but Forever has it: it answered 0 for each Herbalism row (measured 2026-11-27). Forever's `GetTrainerServiceInfo` also carries the required level (return 4).

Forever also has `C_Trainer.GetTrainerType()`.
- Both trainer windows set the filter on every show: available on, unavailable on, used off. A row the filter hides is not in `GetNumTrainerServices()`, and header rows have a cost of 0 and no rank.
- `GetMerchantItemID(index)` exists on both and gives the item id without the item cache. `C_Item.GetItemInfoInstant` exists on both; its sixth return (class 2 weapon, 4 armor) tells a gear vendor.
- Forever's auction house (source-reviewed 2026-11-27, #234): the census lists `C_AuctionHouse` on Forever only; Era's generated documentation lists it too, but the Era client has the list calls instead. The results are tables (`BrowseResultInfo`, `ItemSearchResultInfo`, `CommoditySearchResultInfo`, `ItemKeyInfo`; fields in `tools/recordings/signatures.json`), and the events `AUCTION_HOUSE_BROWSE_RESULTS_UPDATED`, `ITEM_SEARCH_RESULTS_UPDATED` (itemKey) and `COMMODITY_SEARCH_RESULTS_UPDATED` (itemID) say a search has results. `owners` lists seller names and `bidder` is a player GUID: a recording empties or removes them. `C_MerchantFrame.GetItemInfo(index)` returns `MerchantItemInfo` (11 fields; `name`, `currencyID` and `spellID` may be missing).
- Measured 2026-11-27 with CTProbe v8 (Forever 1.60.1.71139): a thread vendor's `C_MerchantFrame.GetItemInfo` (Coarse, Fine and Silken Thread at 10, 100 and 500 copper; `currencyID` and `spellID` absent), a browse search, a Linen Cloth commodity search (21 sellers) and a weapon item search (58 results), each matching its documented structure. A class trainer listed 148 rows on Forever and 115 on Era. Its first trainer event had a count of 0 and the rows came one update later, with the filter already on. A class row's `GetTrainerServiceCost` returns the cost only (no second value), and on Era its subText (return 2) is nil.
- Measured 2026-11-27 with CTProbe v5: an Era weapon vendor (Mace, Hammer, Flail: 1739, 5065 and 7797 copper, `isUsable` false for the two the character cannot use), the `GetItemInfo` of those items, an Era auction link, and the balance beside each window on both clients.
